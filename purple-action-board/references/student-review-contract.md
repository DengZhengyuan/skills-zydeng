# 学生沟通候选审阅契约

该契约用于“学生沟通候选审阅阶段”的对话输出，而不是最终落入 `00 Dashboard/学生沟通面板.md` 的正式页面。

## 固定结构

候选审阅阶段默认按以下顺序输出：

1. 标题
2. 一段简短说明
3. `月度欠账候选`
4. `建议单独细节讨论候选`
5. `建议 long meeting 候选`
6. `可能不再 ongoing 候选`
7. `建议你逐条确认的动作`

## 标题与说明

标题建议固定为：

```markdown
# 学生沟通候选审阅
```

说明区需要简要写清：

- 本次读取范围
- active 学生默认取自所有 `status=ongoing` 的 `log-student`
- 月度覆盖只认 `月度故事汇报` 与 `long meeting`
- 这是候选审阅，不是最终面板

## 月度欠账候选

每条至少包含：

- `学生`
- `最近一次有效覆盖`
- `最近证据`
- `AI 建议动作`
- `建议理由`

`AI 建议动作` 默认只用：

- `保持常规月度`
- `本次不放入`

## 建议单独细节讨论候选

每条至少包含：

- `学生`
- `最近证据`
- `触发原因`
- `建议会前包`
- `为什么这次值得讨论`

## 建议 long meeting 候选

每条至少包含：

- `学生`
- `最近证据`
- `触发原因`
- `建议会前包`
- `为什么这次值得讨论`

## 可能不再 ongoing 候选

每条至少包含：

- `学生`
- `最近证据`
- `AI 建议动作`
- `建议理由`

`AI 建议动作` 默认只用：

- `继续视为 ongoing`
- `建议转 paused`
- `建议转 closed`
- `本次不放入`

## 用户可确认的动作

默认可确认动作：

- `保持常规月度`
- `建议单独细节讨论`
- `建议 long meeting`
- `继续视为 ongoing`
- `建议转 paused`
- `建议转 closed`
- `本次不放入`

## 输出边界

- 不要在候选审阅阶段直接重写 `学生沟通面板`
- 不要把全员台账提前写出来
- 不要把 student log 全文搬进候选
- `触发原因` 应保持短因果句，而不是长段总结
