# AI 行动面板契约

默认页面路径：

- `00 Dashboard/AI 行动面板.md`

该页面是长期存在的固定页面，但内容由 AI 在用户确认后按需重算覆盖。

## 页面固定结构

页面按以下顺序生成：

1. 标题
2. 一段简短说明
3. `眼前动作`
4. `AI 判断：近期重点项目`
5. `近期有变化 / 待你判断重要性`
6. `等待条件`
7. `待确认完成`
8. `可忽略 / 暂不处理`
9. `本次更新时向用户确认的判断`

正式面板不展示候选池，不新增常驻 `候补观察` 区块。空 section 可以保留一句“当前没有需要单独列出的事项”，以保持结构稳定。

## 标题与说明

标题固定为：

```markdown
# AI 行动面板
```

说明区需要简要写清：

- 本次更新时间
- 本次读取的时间范围
- 这是“行动判断层”和“注意力与行动入口”，不是正式任务库
- 本次是否使用了“候选审阅模式”
- 学生沟通判断另见 `[[学生沟通面板]]`

## 每条线程的固定字段

每条线程必须包含以下字段：

- `线程`：一句话命名
- `归属`：`项目 / 学生 / 行政 / 未归类主题`
- `状态`：`近期重点 / 近期有变化 / 等待条件 / 待确认完成 / 可忽略`
- `最近证据`：最近一次明确支持该判断的 note / weekly / log
- `建议下一步`：一句或两句下一步；只在证据明确时写成可执行动作，推测性建议必须用“可考虑 / 待确认”，没有明确动作时写“暂无明确下一步，保持观察 / 等用户判断”
- `为什么现在值得关注`：一句说明优先级或保留理由
- `上次判断`：如果有旧面板中的用户判断，则写出；如果没有，可省略
- `人工修正 / 交互输入`：留给用户下次重算前填写的纠偏字段，默认留空

建议格式：

```markdown
### 线程名

- 归属：项目
- 状态：近期重点
- 最近证据：2026-W13 周总结；2026-03-30 daily
- 建议下一步：整理训练结果图表，并整合进 Paper 3 正文。
- 为什么现在值得关注：已被 recent weekly 标为下周重点，且会影响整条论文收尾节奏。
- 上次判断：继续推进
- 人工修正 / 交互输入：
```

`建议下一步` 的证据边界：

- 来自明确承诺、明确未闭合事项、真实阻塞或高置信度延续线程时，才写成具体动作。
- 来自讨论、追问或 AI 推断时，只能写成“可考虑 / 待确认 / 保持观察”，不能写成已经安排的待办。
- 不要为了每条线程都有动作而硬造下一步。

## 眼前动作的固定字段

`眼前动作` 是全页第一块，负责让用户打开面板后先看到具体动作。该区块固定分成三组：

- `### 未来7天承诺`
- `### 待闭合小事`
- `### 已完成待移出`

每条至少应包含以下字段：

- `事项`
- `最近证据`
- `建议动作`：只写明确短期动作；推测性建议必须用谨慎措辞
- `为什么现在在这个区`
- `上次判断`：如果有旧面板中的用户判断，可写；没有可省略

建议格式：

```markdown
- 事项：完成刘博的数据分析
  最近证据：2026-04-23 daily；[[某主线程]]
  建议动作：这周先把需要补算的 index 算完，再决定是否升级回主线程重点。
  为什么现在在这个区：这是未来 7 天明确强调的短期承诺，本来属于刘博主线程，但当前更需要盯即时动作。
```

## 区块含义

### 眼前动作

放用户最先需要看到的具体动作，不把它写成全量待办清单。

- `未来7天承诺`：来自 recent daily 的 `未来几天需要做的事情`，或用户在候选审阅中明确要求列为短期承诺的动作
- `待闭合小事`：来自 recent daily 的 `今日杂项 / 触发事项`，或需要短期闭合但不足以成为主线程的小尾巴
- `已完成待移出`：已经完成、失效或准备清理出面板，但本轮仍需要让用户看到并确认的动作

如果某项后续反复出现、形成依赖链、或明显牵动主线，应升级为正式线程。如果某项已经完成或明显失效，应进入 `已完成待移出` 或直接移出正式面板。

### AI 判断：近期重点项目

放 AI 判断近期最值得优先推进的主线，默认保持收敛。

- 近期有明确下一步
- 会直接占用用户注意力或行动资源
- 或近期是阻塞点 / 关键节点
- 如果只是从讨论中推测出的合理改进，不进入近期重点；最多进入 `近期有变化 / 待你判断重要性`，并用谨慎措辞

学生相关线程默认进入 `学生沟通面板`；只有直接牵动近期主攻或明确占用用户行动资源的学生线，才进入本区。

### 近期有变化 / 待你判断重要性

放最近有新证据、状态变化或候选价值，但 AI 不确定是否应升为近期重点的项目。

该区块的作用是暴露“可能重要但需要用户修正”的事项，避免 AI 因判断保守而漏掉用户认为重要的项目。

### 等待条件

放重要但当前不该主动推进的线程，例如：

- 外部依赖
- 时机未到
- 用户明确说明暂缓
- 需要先完成别的线程

这些事项不能因为两周没推进就直接消失。

### 待确认完成

放从记录看大概率已完成、已失效、或已被别的线程吸收，但信息还不够完全确认的线程。该区块应尽量短，确认后下次更新应移出面板，并在摘要中留一句。

### 可忽略 / 暂不处理

放有价值但当前有意识地不占注意力的方向。该区块应少用；长期不动的事项应优先留在对应 log / idea 中，而不是常驻行动面板。

## 本次更新时向用户确认的判断

这一节必须显式记录本次候选审阅中的关键确认结果。

至少应包括：

- 本次是否使用了候选审阅模式
- 本次确认放掉的旧条目
- 本次确认 `本次不放入` 的新候选
- 本次从旧区块迁移到 `等待条件 / 待确认完成 / 可忽略` 的条目
- 本次吸收并清掉的 `人工修正 / 交互输入` 中，哪些因为 `#留摘要` 被保留了一句处理结果
- 如果有回捞旧记录中的沉底事项，也应说明这是一轮“遗忘事项回捞”判断

这一节是给下次更新读的，不要写成长篇会议纪要。

## 更新前候选审阅规则

如果已有旧面板，正式落板前默认应先做候选审阅，而不是直接覆盖。

正式面板只承接用户已经确认的结果：

- 用户确认保留或纳入的内容，进入对应区块
- 用户确认 `本次不放入` 的新候选，不进入主板，只进入摘要
- 用户确认 `放掉` 的旧条目，不进入主板，只进入摘要

## 项目字段级人工修正 / 交互输入

`AI 行动面板` 的每个 `### 项目/线程` 字段区，固定允许存在一行字段：

```markdown
- 人工修正 / 交互输入：
```

该字段的用途是给下一次重算提供用户纠偏输入，而不是做永久批注。它只作用于当前项目/线程，不作为整个 section 的纠偏输入。

`眼前动作` 是短期 bullet 区，不给每条事项单独挂输入字段，也不在该 section 顶部保留统一输入字段。如果某条短期事项反复需要纠偏，应优先考虑升级成正式 `### 项目/线程`。

更新规则：

- AI 重算前先读取每个项目/线程字段区里的这些输入
- 当前标准格式是一行字段：`- 人工修正 / 交互输入：`
- 兼容读取旧格式小块：`#### 人工修正 / 交互输入` 及其下方注释内容；生成新版面板时不再输出旧格式小块
- 该输入只影响对应项目，不影响同一 section 下的其他项目
- 已吸收的输入默认从输入字段清掉
- 只有带 `#留摘要` 的输入，吸收后才把结果压成一句写进 `本次更新时向用户确认的判断`
- 没有 `#留摘要` 的输入，吸收后直接清掉
- 未吸收的输入必须继续保留在对应项目下
- 有未处理交互输入的项目，重算时不要随意改 `###` 标题
- 若必须改标题、合并线程或移走项目，必须把旧输入的意图带到新判断里，再清掉旧输入

## 内读源规则

每次更新应写清大致来源范围，例如：

- 上次行动面板之后的新增内容
- 最近 14 天 periodic
- 最近 1 个月 weekly 与关键 logs

用户明确要求时，才扩展到 3 个月。

## 禁止事项

- 不要把页面写成 daily 摘要
- 不要按文件清单罗列来源
- 不要把每条 daily bullet 直接转成线程
- 不要把 `眼前动作` 写成全量待办清单
- 不要默认全量扫描整个 vault
- 不要把 `候补观察` 写进正式面板
- 不要在未经过用户确认时直接覆盖旧面板
- 不要把全员学生台账塞回 `AI 行动面板`
- 不要让学生线程挤占主板；普通学生沟通、月度覆盖、long meeting 与单独讨论判断应由 `学生沟通面板` 承接
- 不要在每个大 section 开头放统一的 `人工修正 / 交互输入`
- 不要给 `眼前动作` 的每条短期 bullet 单独挂输入字段
- 不要生成 `#### 人工修正 / 交互输入` 小标题或 HTML 注释模板
