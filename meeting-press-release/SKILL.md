# meeting-press-release

## 概述

使用这个 skill 撰写中文会议会后新闻稿，而不是泛文案、活动海报文案或学术论文写作。

默认输入是会议日程、会议手册、会务资料、参会名单、发言信息和会后补充事实。默认输出是可直接审改和发布的会议通稿稿包。

## 先锁定任务边界

- 先把任务视为 `会后通稿`，不是会前预告。
- 如果用户明确要写会前预告、会议通知或报名推文，说明这不属于本 skill 的默认目标，再按用户要求谨慎处理。
- 如果用户同时给了已有初稿，进入 `改稿模式`，但仍先核对事实，不直接润色表面措辞。

## 先识别输入材料

先判断用户给了哪些材料，再决定下一步：

- `会议日程 / 议程`
- `会议手册 / 会务手册 / 会议指南`
- `参会人名单 / 嘉宾名单 / 主持与发言安排`
- `讲话稿 / 发言提纲 / 开幕词 / 致辞`
- `会后事实 / 现场亮点 / 结果信息 / 引语`
- `已有新闻稿初稿`

先从材料中抽取并固定以下基础信息：

- 会议名称
- 主办、承办、协办或支持单位
- 时间
- 地点
- 会议主题或主线
- 议程结构
- 关键人物及身份

如果同一信息在多份材料中冲突，优先保守处理，并明确指出冲突点。

## 风格判断

默认支持两种风格：`机构新闻` 与 `媒体报道`。

- 用户提到“官网、公众号、学校、学院、单位、主办方通稿、官方发布”等，默认走 `机构新闻`。
- 用户提到“新闻感、报道、媒体风格、记者稿、媒体口吻”等，默认走 `媒体报道`。
- 如果用户没有给出明显信号，只补问一句：`这次按机构新闻还是媒体报道来写？`

需要风格细化时，读取 [references/style-modes.md](references/style-modes.md)。

## 固定执行流程

始终按以下顺序执行，不跳步：

1. 识别材料类型并提取已知事实。
2. 读取 [references/missing-info-checklist.md](references/missing-info-checklist.md)，检查会后通稿必需事实是否齐全。
3. 如果关键事实缺失，停止正式成稿，先输出 `待补信息清单`。
4. 如果关键事实充分，先确定新闻角度、核心信息层级和段落结构。
5. 默认先给出提纲。
6. 用户确认提纲后，再输出完整稿包。

如果用户明确说 `直接出全文`：

- 仍然先做事实检查和内部提纲。
- 不必把提纲单独展示给用户。
- 直接输出完整稿包。

## 缺口检查规则

起草前必须确认至少具备以下关键信息：

- 会议确已召开，而不是仅计划召开
- 基本会议信息清楚：名称、时间、地点、主办方
- 实际出席或参与情况有据可依
- 会议产生了可写入新闻稿的结果信息
- 至少有一类可支撑新闻性的内容

可支撑新闻性的内容包括：

- 核心结论
- 现场亮点
- 关键引语
- 发布、签约、授牌、表彰、启动、揭牌等结果

如果上述内容不足，不要硬写“成功召开、取得圆满成功、达成广泛共识”等空泛套话。先按 [references/output-contract.md](references/output-contract.md) 的缺信息格式输出。

## 提纲阶段

默认先给出提纲，提纲应服务于后续成稿，而不是做泛泛摘要。

提纲至少包含：

- 新闻主角度
- 标题方向
- 导语要写的关键信息
- 正文段落安排
- 哪些事实已经确认
- 哪些信息仍需补齐

提纲要短，但必须足够让用户判断结构是否正确。

## 完整稿包阶段

正式成稿时，始终读取 [references/output-contract.md](references/output-contract.md)，按固定结构输出。

默认完整稿包包含：

- `标题候选` 3 个
- `导语` 1 段
- `正文`
- `发布摘要`

除非用户明确要求，不额外输出长篇解释、逐句修改说明或风格分析。

## 改稿模式

当用户提供已有初稿时：

1. 先把初稿当成一个信息来源，而不是事实本身。
2. 用原始会议材料校对初稿中的事实、身份、时间和结果表述。
3. 保留成立的事实，重写弱标题、弱导语、堆砌套话和失衡段落。
4. 不为了增强“新闻感”而新增未被材料支持的判断。

## 写作约束

- 不编造会后结果。
- 不把计划、议程或期待写成既成事实。
- 不夸大会议规格、影响力或成果。
- 不堆砌“隆重召开、圆满举行、反响热烈”等空话，除非材料明确支持且确有发布价值。
- 不把机构新闻和媒体报道的语气混写在同一稿件里。
- 不在已知信息充足时反复追问细枝末节。
- 不在关键信息不足时直接进入全文写作。

## 使用 references 的顺序

默认按以下顺序读取 references：

1. [references/missing-info-checklist.md](references/missing-info-checklist.md)
2. [references/style-modes.md](references/style-modes.md)
3. [references/output-contract.md](references/output-contract.md)
4. [references/style-guide.md](references/style-guide.md)

如果用户提供了固定口径样稿，优先阅读 `references/examples/` 中的真实样稿，再回到 `style-guide.md` 执行。

## 样稿基准

`references/examples/` 目录用于存放 3-5 篇真实会议新闻/通稿样稿。

- 当样稿尚未补齐时，先按 `style-guide.md` 的通用规则执行。
- 当样稿已补齐时，优先提炼样稿中的固定口径、标题习惯、导语节奏、段落顺序和收束方式。
- 当样稿规则与通用规则冲突时，优先遵循真实样稿，但不能违反事实保守原则。

## 典型触发语句

以下表达应触发这个 skill：

- `根据会议日程和会议手册写一篇会后通稿`
- `把这套会议材料整理成官网新闻`
- `按媒体报道风格写这次会议新闻稿`
- `我有一版会议新闻初稿，帮我按会务资料重写`
- `根据议程、嘉宾名单和会后亮点写公众号新闻稿`
