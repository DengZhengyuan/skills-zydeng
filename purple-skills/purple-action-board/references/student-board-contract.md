默认页面路径：

- `00 Dashboard/学生沟通面板.md`

该页面用于维护全体 `ongoing` 学生的沟通覆盖、升级建议与台账，不替代 `AI 行动面板.md`。

## 页面固定结构

页面按以下顺序生成：

1. 标题
2. 一段简短说明
3. `本周需处理`
4. `月度欠账`
5. `建议单独细节讨论`
6. `建议 long meeting`
7. `可能不再 ongoing`
8. `全员台账`
9. `本次更新时确认的判断`

## 标题与说明

标题固定为：

```markdown
# 学生沟通面板
```

说明区需要简要写清：

- 本次更新时间
- 本次读取范围
- active 学生默认来自所有 `record_type=log-student` 且 `status=ongoing` 的 notes
- 这是“学生沟通判断层”，不是正式任务库，也不是学生考核表

## 前半页分流区块

### 本周需处理

只放当前一周最值得立刻安排的学生条目。

适合进入这里的情况：

- 已经欠一次月度正式覆盖
- 已明确建议单独细节讨论
- 已明确建议 long meeting
- 虽未欠账，但最近出现高优先级异常信号

每条至少包含：

- `学生`
- `当前建议`
- `最近证据`
- `建议下一步`：只写明确需要本周安排的沟通动作；推测性判断写成“可考虑 / 待确认”
- `为什么这周要处理`

### 月度欠账

只放超过 `28` 天没有有效月度覆盖的 `ongoing` 学生。

有效覆盖只包括：

- `月度故事汇报`
- `long meeting`

`单独细节讨论` 不计入月度覆盖。

每条至少包含：

- `学生`
- `最近一次有效覆盖`
- `最近证据`
- `建议动作`：通常是安排一次月度故事汇报；不要附加未经确认的额外待办
- `为什么判为欠账`

### 建议单独细节讨论

放问题边界相对清楚、适合 `30-60` 分钟局部讲透的学生。

每条至少包含：

- `学生`
- `最近证据`
- `触发原因`
- `会前包`

### 建议 long meeting

放需要从 `0` 讲清整条课题逻辑的学生。

每条至少包含：

- `学生`
- `最近证据`
- `触发原因`
- `会前包`

### 可能不再 ongoing

放当前仍是 `status=ongoing`，但从近况看可能已不适合继续算 active 的学生。

每条至少包含：

- `学生`
- `最近证据`
- `AI 建议`
- `建议理由`

`AI 建议` 只使用：

- `继续视为 ongoing`
- `建议转 paused`
- `建议转 closed`

## 全员台账

全员台账按学生逐条列出，每位 `ongoing` 学生一条。

每条固定字段：

- `学生`
- `当前建议`：`继续常规月度 | 建议单独细节讨论 | 建议 long meeting | 观察`
- `最近一次月度故事汇报`
- `最近一次单独细节讨论`
- `最近一次 long meeting`
- `最近证据`
- `本次主要汇报 / 当前主线`
- `触发原因`
- `下次若约需准备`：只写明确需要准备的材料；推测性建议必须用“可考虑 / 待确认”，没有明确动作时写“保持常规观察”

建议格式：

```markdown
### 张舒瑞

- 当前建议：继续常规月度
- 最近一次月度故事汇报：[[20260401 EIT 流态化闲聊会]]
- 最近一次单独细节讨论：无
- 最近一次 long meeting：无
- 最近证据：[[20260401 EIT 流态化闲聊会]]；[[log 2024 张舒瑞]]
- 本次主要汇报 / 当前主线：汇报了 revolving bed / 转鼓与 AI 图像处理结合的阶段思路和基础准备。
- 触发原因：当前主线和下一步动作已较清楚，暂时不需要升级沟通形式。
- 下次若约需准备：带一版结合现有数据的初步分析图。
```

学生沟通建议的收紧规则：

- `建议单独细节讨论` 和 `建议 long meeting` 必须有明确证据，例如 student log 中的稳定沟通建议、反复未闭合的技术定义 / 路线问题、或用户确认。
- 不把一次普通追问、一次报告中的潜在改进点、或 AI 推断出的“可能需要聊聊”直接升级成沟通建议。
- 证据不足但值得关注时，写成 `观察` 或放入候选审阅，让用户确认。

## 本次更新时确认的判断

至少应包括：

- 本次是否使用了候选审阅模式
- 本次确认纳入 `月度欠账` 的学生
- 本次确认纳入 `建议单独细节讨论` 的学生
- 本次确认纳入 `建议 long meeting` 的学生
- 本次确认保持 `ongoing` 或建议转 `paused / closed` 的学生
- 本次确认 `本次不放入` 的候选

## 禁止事项

- 不要把页面写成考核表或打分表
- 不要把全部 meeting note 摘要原样搬过来
- 不要把所有学生都放进 `本周需处理`
- 不要跳过 `全员台账`
- 不要直接改学生 log 的 frontmatter 状态，除非用户明确要求写回
